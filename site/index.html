Proof it works

real pictures, located in Babel and fetched back

A random frame almost never contains a picture, so we ran the pipeline backwards: we drew these pictures, asked Babelia's image search for their location in the archive, then fetched each location back with the scanner's own code and scored it. Their locations have about 960,000 digits each, which is why the slideshow, starting below 1016, never reaches them.

How detection works

Each Babel pixel is an independent random 12-bit colour, so instead of asking “what is this a picture of?” the detector asks “how unlikely is this frame if it were pure static?”. It runs ten statistical tests on brightness and both colour channels. Each test's result is measured in σ (standard deviations away from what static produces), calibrated on simulated static that uses Babelia's own JPEG encoding and checked against real frames.

shaperegions, gradients and large shapes that survive block-averaging (4–64 px)
blobsmall strong objects: the most extreme sliding window, 8–48 px
lineshorizons, stripes and bands: rows and columns, 1–8 px thick
textureneighbouring pixels that agree (smooth) or alternate (checkerboards)
palettecolour channels that move together (greyscale or limited palettes)
tonehistogram skew: too dark, too bright or too few colours
contrastpatches flatter or noisier than static, even when their average colour blends in
angledlines and bands at 15° steps between the rows and columns
repetitionany part of the frame recurring at an offset: tiles and repeated motifs
symmetrymirror symmetry about any vertical or horizontal axis

Thresholds

ScoreTierWhat happens
< 3σstaticcounted, discarded
3 – 4σnear misstop 12 kept as “closest calls”
4 – 8σanomalysaved as a find, with its location (seed) and image
8 – 16σfaint
16 – 40σclear
≥ 40σstriking

Anomalies are the strangest static the scanner has met: about 1 in 400 random frames lands there by chance. Real static has never reached 8σ in calibration, so a find at 8σ or above would mean a genuine pattern.
